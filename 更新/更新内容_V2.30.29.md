# 班级管理系统 V2.30.29 更新说明

- 发布日期：2026-10-04
- 类型：缺陷修复（插件健壮性）
- 上一版：V2.30.28+95 ｜ 本版：V2.30.29+96

## 本版修了什么

| 问题 | 后果 | 修复 |
| --- | --- | --- |
| 插件 id 直接当**文件夹名**，但只查了"程序保留名"，没查 Windows 文件系统限制 | id 为 `con` / `prn` / `aux` / `nul` / `com1`(及 lpt1) 时创建目录失败；id 以点结尾（`abc.`）会被系统**静默去点**、与另一个 id 撞车 | id 同时校验 Windows 保留设备名（含 `con.txt` 这种带扩展名形式）与尾随点，命中即拒绝并说明原因 |
| `apiVersion` **类型不对时静默按当前版本处理** | 写着 `"2"`（字符串）或 `2.0` 的插件被当成兼容版本跑起来，行为不可预期 | 字段存在但类型不对 → **明确报错**；字段缺失仍按兼容处理（老插件不受影响） |
| 插件包（zip）路径只拦了 `..` 与绝对路径 | NTFS 数据流（`a:b`）、非法字符（`<>"|?*`）、以点/空格结尾、保留设备名都能溜进解压流程 | 改为**逐段白名单校验**：任一段非法即整包拒绝 |
| **目录式插件没有体积上限**（zip 导入有检查，直接拷目录没有） | 一个超大入口脚本会被一次读进内存，可能撑爆程序 | 入口脚本超过 4 MB 直接拒绝加载（列表里给出明确原因） |
| 插件返回的列表类字段（选项/列/标签/系列/命令…）**没有长度上限** | 插件返回超大列表会把插件页拖垮、吃内存 | 列表条目 ≤200、单个文本 ≤2000 字、单个对象 ≤50 个键 |
| 插件追加工作表**没有上限**，还能用同名（如"汇总"）让程序**复用自己的内置表** | 插件能把行追加进程序的"汇总/明细/考勤"表里，**污染导出**；表太多/行太多也会撑爆导出 | 与内置表同名的一律跳过；表数量 ≤5、每表行 ≤2000、列 ≤50 |
| 插件脚本**加载阶段的错误被丢弃** | 脚本有语法错误时，用户看到的是 "run is not defined"（指向错误方向，白排查） | 如实报出"插件脚本加载失败：<真实原因>" |
| 插件角标刷新在**加载期间到来的请求被丢弃**且不再重试 | 数据变了但角标一直停在旧值（永不刷新） | 记下最新一次请求，本轮加载结束后自动再刷一次 |
| **示例插件**的"导出报表"里读的 `student.attendance` 是早就搬走的字段 | 示例导出表里"考勤异常"列**恒为空**（静默失效） | 改读顶层 `attendance.byStudent`（与试跑/角标口径一致） |

## 用户能感知到的变化

- 插件安装更安全：坏 id、坏路径、超大脚本、超大返回内容都会被明确拦下并说明原因。
- 插件不再能污染程序自己的统计报表工作表。
- 插件出错时提示的是**真正的原因**，不再是误导性的 "run is not defined"。
- 插件角标会正常跟随数据刷新。
- 内置示例插件的导出表能正确显示考勤异常了。
