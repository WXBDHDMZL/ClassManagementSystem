## 本版改了什么

### 三、数据完整性

| 编号 | 问题 | 修复 |
| --- | --- | --- |
| **G-5** | 导入考勤时透传外部包里的 `syncedRecordId`，与本机记录撞号后删本机记录会连带删掉这条导入考勤 | 导入新增分支统一 `copyWith(syncedRecordId: '')`，外部链接一律清空 |
| **G-11** | 删除记录后，指向它的考勤留下悬空 `syncedRecordId`（链接语义腐坏） | 收集本次删除的 id，跨日期清空指向它们的考勤链接并置 `syncedFromRecord:false` |
| **G-21** | 备份 `.bak` 用 `file.copy` 直接覆盖，中途掉电会留下截断的备份 | 新增 `AtomicFile.copyAtomic`（临时文件 + rename），备份与主文件写入分别独立 try |
| **G-32** | 时间越界时被"钳制"到边界值，把脏数据洗成看似合法 | `_normalizeTime` 超范围返回 `'00:00:00'`，不再钳制 |
| **G-3** | `addRecord` 未校验操作类型 / 传入日期 / 记录 id | 操作类型白名单（表扬/批评）、非法日期回退归属日、`recordId` 查重后再用 |
| **S-10** | 数据包内校历键 / 同步映射键未校验 | 校历键须为合法日期；`syncMap` 键须在包内 `attendanceStatuses` 内 |

### 四、健壮性

| 编号 | 问题 | 修复 |
| --- | --- | --- |
| **G-2** | `AppData.students` / `reasons`（及其内部 Map）是公开可变集合，界面一句 `.clear()` 就静默清空且不落盘、不通知 | 名单改为私有 + 只读视图（`UnmodifiableListView`），变更走 `setStudents/addStudent/removeStudent/replaceStudentAt/moveStudent`；原因库内部 Map 私有化，对外只给只读视图与 `addReason/renameReason/removeReason/reorderReason` |
| **G-18** | 值对象没有 `==`/`hashCode`，集合去重 / 包含判断依赖对象引用 | 为 `StudentRecord` / `AttendanceRecord` / `PluginManifest` / `ReasonLibrary` 补值相等（原因库分组顺序无关，组内顺序有语义） |
| **G-22** | 原子写队列 `_queues` 只增不删 | 队尾完成后若仍是本队尾则移除条目，避免 Map 无限增长 |
| **G-25** | 插件 zip 导出 / 内置插件写入非原子，失败时可能留下半个文件 | `exportZip` 改原子写并返回错误；`_writeBuiltinPlugin` 改原子写两文件 + 失败回滚备份 |
| **G-4** | `_parseDate` 自有一套年份口径，与 `isValidYmdDate` 不一致 | 统一走 `isValidYmdDate` 前置校验 |
| **G-7** | 原因改名不回溯历史记录，旧记录再编辑时按原因反查映射不命中，会撤销原本关联的考勤 | 改名同时改写历史记录中的原因文本 |
| **G-8** | `setStatisticsChart` / `setRecordDefaults` 入口不 clamp，非法值运行期生效、重启才清洗 | 入口 `clamp(0,2)`，与 `fromJson` 口径一致 |

| **G-50** | 记录列表考勤按钮整块订阅 provider，任意变更都重建 | 改 `context.select` 窄订阅，只在"考勤开关"变化时重建 |

## 构建脚本修复（非用户可见）

- **问题**：程序带系统托盘，关闭主窗口后常驻后台；Windows 上正在运行的 exe
  无法被覆盖，此时重新构建会报 `LNK1104: 无法打开文件 ...班级管理系统.exe`，
  必须手动去托盘/任务管理器关掉程序才能构建成功（此前频繁出现）。
- **修复**：新增 `tools/stop_app_instances.py`，并在 `build.bat` 与
  `installer/build_installer.bat` 的最前面调用它 —— 构建前自动结束正在运行的
  程序实例并等待句柄释放；若因权限不足（例如程序以管理员身份启动）结束不掉，
  则**提前退出并给出明确提示**，而不是让链接器抛一句难懂的 LNK1104，也省掉一次
  无效构建。
- 已实测：程序运行中直接执行 `build.bat`，自动结束后构建成功。
