# 班级管理系统 V2.30.31 更新说明

- 发布日期：2026-10-04
- 类型：清理收口（顶部提示框加固 + 去重/魔法数字/死代码/孤儿注释）
- 上一版：V2.30.30+97 ｜ 本版：V2.30.31+98

## 本版修了什么

### 一、顶部提示框（X-33）

| 问题 | 后果 | 修复 |
| --- | --- | --- |
| 顶部提示（"已删除""密码错误"等）2 秒后**无条件**移除，且**从不释放** | 计时结束时若界面已关闭/路由已替换，条目仍被引用；重复触发时可能命中"只能移除一次"的断言，且资源一直不释放 | 改为**只移除、释放一次**：用本地标志保证幂等，`remove()` 后补 `dispose()`；Overlay 已销毁时安全早退 |

### 二、去重（同一逻辑只留一份）

| 位置 | 处理 |
| --- | --- |
| 日期显示 `_formatDate` 在 `record_list.dart` 与 `attendance_dialog.dart` **各写一份**（后者还带一个永不触发的 try/catch） | 统一为 `utils/app_date.dart` 的 `formatChineseDate` |
| 对话框宽度封顶写法在**考勤/统计/日志 3 处**重复，且字面量 700/720 混用 | 统一为 `app_theme.dart` 的 `kDialogMaxWidth` / `dialogWidthFor()` |
| 考勤饼图的"暗色梯度"透明度公式在**扇区与图例各写一遍** | 统一为 `_pieSliceAlpha()` |

### 三、魔法数字 → 具名常量

- 统计"需关注"分界 `10 / 45` → `attentionWeekMaxDays` / `attentionMonthMaxDays`
- 名单排序哨兵 `1 << 20`（考勤排序、数据包排序）→ 具名局部常量
- 日期年份范围 `1900 / 2100` → `kMinSupportedYear` / `kMaxSupportedYear`（日期校验与统计解析共用）
- 日期区间上限 `3700` 与校历导入 `3660` **不一致** → 统一为 `kMaxDateRangeDays`
- 插件工作表名截断 `28` → `maxPluginSheetNameLength`（注释原写"上限 31"与实际不符，已改准）

### 四、死代码 / 孤儿注释

- 操作日志写队列外层 `.catchError` **永远不可达**（内层已全捕获）→ 删除
- "关于"页：无状态的 `StatefulWidget` 外壳 + 孤儿的字段注释 + 重复间距 → 改回 `StatelessWidget` 并清理
- `app_theme.dart` 一条**下方无声明**的孤儿文档注释 → 删除
- `record_dialog.dart`：`selectedStudents` 传入恰好 1 人时的接口陷阱 → 加断言拦下（debug 期即报错）
- 插件导出对话框**两层 `StatefulBuilder` 外层多余** → 收敛为一层
- 排名导出 `praiseSheet` 首个 `appendRow` **缩进错乱** → 修正
- CSV 解码的 BOM 判断用**字面量不可见字符** → 改用 `'\uFEFF'`
- 界面错误占位整组硬编码颜色 → 补注释说明"主题损坏兜底"的豁免理由

## 用户能感知到的变化

- 顶栏提示出现/消失与以往一致；极端情况下（提示期间关窗、换页）**不再有潜在崩溃**。
- 界面观感**无功能变化**（对话框宽度统一为 700，视觉差异可忽略）。
- 程序更"干净"：同一逻辑不再有两份实现，后续维护更不易漂移。
