# 班级管理系统 V2.30.21 更新说明

- 发布日期：2026-10-04
- 类型：缺陷修复（数据解析健壮性）
- 上一版：V2.30.20+87 ｜ 本版：V2.30.21+88

## 本版修了什么

| 问题 | 后果 | 修复 |
| --- | --- | --- |
| 加载数据时，`recordsByDate` / `settings` 若类型不对，会**直接抛类型错误**，被判定为"整个数据文件损坏" | 哪怕只有一处字段类型异常，程序也会走"数据重置/从备份恢复"链，**本来能读出来的记录/名单/设置全部一起丢** | 改为安全判型：类型不对的那一块当空处理，**其余字段照常解析**，尽量把能救的数据都读回来 |
| 记录/考勤的**分组键（日期）不校验** | 极少数脏数据会让记录挂在非法日期下，在历史、导出、统计里**永远显示不出来**（等于静默吞数据） | 分组键必须是真实存在的日期；非法时优先用记录自带的合法日期**抢救归位**，实在无法归位才丢弃，并写入错误日志 |
| 考勤解析与记录解析**不对称** | 考勤不校验桶键日期、不用桶键回填 `date`、丢弃条目不计数也不写日志（记录侧早就做了这三件事） | 考勤解析与记录侧**完全对齐**：校验桶键、回填日期、丢弃记数并写日志 |
| 整包还原时，考勤"跳过"原因**混成一个计数** | 日志把"状态非法 / 重复"也写成"跳过日期非法 N 条"，事后核对日志会被误导 | 三类原因**分别计数**并按需列出（日期非法 / 状态非法 / 重复），只显示非零项 |

## 用户能感知到的变化

- 数据文件局部损坏时，**能救的记录不会再被整份丢掉**。
- 不会再有"记录莫名不见了"（挂在非法日期下、界面永远不显示）的情况。
- "整包还原"后的日志能如实说明到底跳过了什么，便于排查。
